# Klavar for Android and iOS

Klavar converts sheet music into Klavarskribo, piano roll, falling notes, numbered
notation (jianpu), proportional and engraved staff views, and plays it back.
This folder holds the Android and iOS apps (one shared codebase) and an optional scan server
that reads music from photos.

```
klavar-app/
  www/                  the app itself (index.html plus bundled libraries, works offline)
  android/              the native Android project (generated by Capacitor)
  ios/                  the native iOS project (generated by Capacitor, Swift Package Manager)
  server/               photo and PDF scan server (Python, oemer, Docker)
  .github/workflows/    builds and publishes releases, and checks the iOS build, on GitHub
  tools/                one-time setup helpers
```

## 1. Build the app

### Option A: let GitHub build it (no Android Studio needed)

1. Create a new private repository on GitHub and upload this whole folder.
2. Open the **Actions** tab. The "Build and publish Klavar" workflow runs on every push
   to `main` (or press **Run workflow**).
3. When it finishes, open the repo's **Releases** page and download `klavar.apk`.
   Set up automatic updates (section 7) before you install it for real.

### Option B: build on your own computer

You need Node.js 22 or newer, and Android Studio (which brings the Android SDK and Java 21).

```
npm install
npx cap sync android
npx cap open android        # opens Android Studio, then press Run with your phone plugged in
```

or from the command line: `npm run build:debug`. The APK lands in
`android/app/build/outputs/apk/debug/app-debug.apk`.

## 2. Install it on your phone

Copy `app-debug.apk` to the phone and open it. Android will ask you to allow installs
from that source (Files app or browser); allow it once. On later builds, install the
new APK over the old one and your settings and last piece are kept.

## 2b. Build and install the iOS app

iOS apps can only be built on a Mac with Xcode (free from the Mac App Store, version 16 or newer).

```
npm install
npx cap sync ios
npx cap open ios            # opens the project in Xcode
```

In Xcode:

1. Click **App** in the left sidebar, then the **Signing & Capabilities** tab.
2. Tick **Automatically manage signing** and pick your **Team**. A free Apple ID works for
   installing on your own iPhone; add it under Xcode > Settings > Accounts.
3. If Xcode says the bundle identifier is taken, change `com.gahoose.klavar` to something
   unique to you (and use the same value in `capacitor.config.json`).
4. Plug in your iPhone, choose it as the run destination at the top, and press **Run**.
5. The first time, the iPhone asks you to trust the developer: Settings > General >
   VPN & Device Management, tap your Apple ID, then Trust. On iOS 16 and later also turn on
   Settings > Privacy & Security > Developer Mode.

With a free Apple ID the app stops opening after 7 days; press Run again to reinstall it.
A paid Apple Developer Program membership ($99 a year) removes that limit and lets you
use TestFlight and the App Store.

No Mac? The release pipeline builds the iOS app on a GitHub Mac on every push (free for
public repositories). See section 8 for getting it onto an iPhone without a Mac.

### iOS notes

- Sound plays even with the ring/silent switch set to silent. Headphones and Bluetooth work as usual.
- The first scan asks for camera access, and the first time it reaches your scan server
  iOS asks for local network access. Allow both. If you declined, re-enable them in
  Settings > Klavar.
- Plain `http://` scan servers on your Wi-Fi are allowed. For anything outside your home
  network, use HTTPS: Tailscale's `tailscale serve` or any HTTPS host works.

## 3. Set up photo scanning

Scanning runs on a computer, not on the phone, because music recognition needs far
more processing power than a phone can give it in reasonable time.

1. Install Docker Desktop on a PC that's on the same Wi-Fi as your phone.
2. In this folder's `server` directory run:
   ```
   docker compose up -d --build
   ```
   The first build takes several minutes because it downloads the recognition models.
3. Find the PC's local IP address (Windows: `ipconfig`, look for IPv4, e.g. `192.168.1.20`).
   Allow port 8000 through the PC's firewall if asked.
4. Check it from the phone's browser: `http://192.168.1.20:8000/health` should say `{"ok":true}`.
5. In the app, enter `http://192.168.1.20:8000` under **Scan server address**.

Then tap **Scan with camera** or **Scan image or PDF**. A page usually takes one to three
minutes. PDFs scan their first page only.

**Using it away from home:** put the server on a cloud machine or reach your home PC through
a VPN such as Tailscale. If the server is reachable from the internet, set `SCAN_TOKEN` in
`docker-compose.yml` to a password and enter the same password in the app's
**Scan access key** field.

**Getting good results:** photograph one page, flat and straight on, in even light, filling the
frame. Printed music works far better than handwriting. Expect some mistakes on dense piano
writing: open **Edit notes** after a scan to fix them, then play it back to check.

## 4. Changing the app

Edit `www/index.html`, then run `npx cap sync` (updates both apps) and rebuild. The app's ID is
`com.gahoose.klavar`; change `appId` in `capacitor.config.json` before your first store
release if you want a different one (it can't change afterwards).

## 5. Publishing on Google Play

1. Create a Google Play developer account (one-time fee).
2. In Android Studio choose **Build > Generate Signed App Bundle**, create an upload key,
   and keep the keystore file and its passwords somewhere safe. You need them for every update.
3. Upload the `.aab` in the Play Console, fill in the store listing, content rating and privacy
   form (mention that scans are sent to your own server), and start with internal testing.
4. Replace the default app icon first: `npx @capacitor/assets generate` creates all icon sizes
   from a single 1024x1024 image in `assets/icon.png`.

## 6. Publishing on the App Store

1. Join the Apple Developer Program.
2. In App Store Connect create a new app with the same bundle identifier.
3. In Xcode choose a real device or "Any iOS Device", then **Product > Archive**, and
   **Distribute App > App Store Connect**. The build appears in TestFlight for testing.
4. Fill in the listing, screenshots, age rating and the privacy questions (scans are sent
   to a server you run; nothing else leaves the phone), then submit for review.
5. Set the icon first: `npx @capacitor/assets generate` fills in both the Android and iOS icons.

## 7. Automatic updates without an app store

Every push to `main` builds the app and publishes a GitHub release. Installed apps check that
release when they open (and when you switch back to them, at most every 30 minutes), or when
you tap **Check for updates** at the bottom of the panel.

There are two kinds of update:

- **Everyday updates (no reinstall).** Changes to anything in `www/` (all of Klavar's features)
  are downloaded in the background. A bar appears: tap **Restart now**, or the update applies
  next time you open the app. If an update ever fails to start, the app automatically rolls
  back to the previous version.
- **App updates (rare).** Changes to native parts (new Capacitor plugins, permissions,
  `capacitor.config.json`, anything in `android/`) need a new APK. When you make one, add 1
  to the number in `native-version.txt`. Installed apps then show **Download**, which fetches
  the new APK; tap it to install over the old one. Android always asks you to confirm an
  install from outside the Play Store; that step can't be automated.

### One-time setup

1. **Permanent signing key.** Android only installs an update if it is signed with the same
   key as the installed app. In your Codespace run:
   ```
   bash tools/make-signing-key.sh
   ```
   and follow what it prints to save the `ANDROID_DEBUG_KEYSTORE` secret. Download
   `klavar-debug.keystore` from the file panel and keep it safe.
2. **Let the app download releases.** Release files in a private repository can't be
   downloaded by the app. Either:
   - make this repository public (Settings > General > Change visibility; your secrets stay
     secret), or
   - keep it private and publish releases to a second, public repository: create an empty
     public repo with a README (for example `klavar-releases`), create a fine-grained personal
     access token with **Contents: Read and write** on that repo, then in this repo add the
     secret `RELEASE_TOKEN` (the token) and the variable `RELEASE_REPO`
     (`your-name/klavar-releases`) under Settings > Secrets and variables > Actions.
3. Push any change (or press **Run workflow**). When the release appears, **uninstall** any
   Klavar you installed earlier (it was signed with a temporary key), then install `klavar.apk`
   from the latest release. From now on, updates arrive by themselves.

On iPhone, everyday updates work the same way once the app is installed. App updates still
have to be installed from Xcode or TestFlight, because Apple doesn't allow installing apps
from a download link.

## 8. iOS builds in the pipeline

Every release now also contains `klavar-unsigned.ipa`, built on a GitHub Mac. If the iOS build
ever fails, the Android release still goes out.

iPhones only run apps signed by Apple, so there are two ways to use it:

**TestFlight (recommended, fully automatic, no Mac needed).** Requires the Apple Developer
Program ($99 a year).

1. In App Store Connect > Apps, create a new app with bundle ID `com.gahoose.klavar`
   (register the ID under Certificates, Identifiers & Profiles > Identifiers first).
2. In App Store Connect > Users and Access > Integrations > App Store Connect API, create a
   key with the **Admin** role. Download the `.p8` file (you only get one chance) and note the
   Key ID and Issuer ID.
3. Find your Team ID under Membership details on developer.apple.com.
4. Add four repository secrets (Settings > Secrets and variables > Actions), or from your
   Codespace after uploading the `.p8` file:
   ```
   gh secret set APPSTORE_KEY_ID --body "YOUR_KEY_ID"
   gh secret set APPSTORE_ISSUER_ID --body "YOUR_ISSUER_ID"
   gh secret set APPLE_TEAM_ID --body "YOUR_TEAM_ID"
   gh secret set APPSTORE_KEY_P8 < AuthKey_YOUR_KEY_ID.p8
   rm AuthKey_YOUR_KEY_ID.p8
   ```
5. Push. Each build is signed and uploaded to TestFlight. Install the TestFlight app on the
   iPhone, accept the invite (add yourself under TestFlight > Internal Testing), and new native
   versions install from there. Everyday updates still arrive over the air.

**Sideloading the unsigned IPA (free Apple ID).** Tools such as SideStore or AltStore re-sign
the IPA with your own Apple ID. They need a computer (Windows works) for the first setup, and
free-account apps must be refreshed every 7 days.

## 9. Updating from a phone (no Codespace needed)

Changes can arrive as a file named `klavar-update-<something>.zip`. To apply one:

1. On github.com (Chrome, Desktop site on), open the repository's main page.
2. Tap **Add file > Upload files**, choose the zip, and tap **Commit changes**.

The **Apply update zip** workflow unpacks it over the project, deletes the zip, commits, and
starts a new release build. Installed apps then update themselves as usual.

Workflow files (in `.github/workflows`) can't be changed this way, because GitHub doesn't let
automated jobs edit workflows. Upload those by hand: open the `.github/workflows` folder on
github.com, then **Add file > Upload files**; a file with the same name replaces the old one.
